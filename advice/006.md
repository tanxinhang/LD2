是的，我建议**先做 L0 通信余量回收，再做 D0.93-A2**。但 L0 的定位要非常克制：它不是新的主算法，而是一个**物理上必须先排除的资源错配层**。

当前系统里通信与感知共享严格的 (1,\mathrm W) 预算，

[
P_{{\rm comm},i}+\sum_q P_{{\rm sense},iq}=1,
]

并且当前 U2U Token 链路采用正交带宽、Shannon 串行化、SNR 门限和 deadline 判定。也就是说，通信功率多留一分，就明确少一分 sensing budget。

所以在把 (\gamma_P^\star>1) 归因于“结构不够”之前，确实应该先问：

[
\boxed{\text{当前 }P_{\rm comm}\text{ 是否只是给多了？}}
]

但我建议把 L0 做得比“直接把通信功率降到最小”更严格。

------

## 1. L0 的核心原则：保持通信语义不变，只回收 link margin

固定当前 epoch 的：

- active Tx 集合；
- Token 内容与量化精度；
- packet bits (L_i)；
- 接收/必须送达集合 (\mathcal R_i)；
- bandwidth allocation；
- role / owner / structure；
- deadline；
- packet-delivery 判据。

只优化：

[
P_{{\rm comm},i}.
]

那么 L0 是：

[
\boxed{
\min_{{P_{{\rm comm},i}}}
\sum_iP_{{\rm comm},i}
}
]

s.t.

[
\text{原本要求送达的所有 U2U packets 仍满足通信约束}.
]

这里非常重要：

> **不能同时减少 Token bit、删 receiver、改结构或放宽 deadline。**

否则就无法区分“功率余量”与“协议重构”的贡献。

------

# 2. 以当前通信模型，其实可以先写出解析最小功率

当前模型中，活跃发送者正交平分 (100,\mathrm{kHz})，链路速率按 Shannon 计算，并要求：

[
{\rm SNR}*{ij}\ge \Gamma*{\rm th},
]

同时

[
\frac{L_i}{R_{ij}}+T_{\rm proc}
\le T_{\rm ddl}.
]



固定活跃发送者数量以后，(B_i) 已知。

deadline 要求等价于：

# [ R_{ij} \ge R_i^{\rm req}

\frac{L_i}{T_{\rm ddl}-T_{\rm proc}}.
]

又因为

# [ R_{ij}

B_i\log_2(1+\Gamma_{ij}),
]

所以需要：

[
\Gamma_{ij}
\ge
2^{R_i^{\rm req}/B_i}-1.
]

因此实际最低 SNR 为

# [ \boxed{ \Gamma_i^{\rm req}

\max
\left{
\Gamma_{\rm th},
2^{\frac{L_i}{B_i(T_{\rm ddl}-T_{\rm proc})}}-1
\right}.
}
]

假定当前通信核的链路增益为 (g_{ij})，噪声功率为 (N_0B_i)，则

# [ P_{ij}^{\rm req}

\frac{\Gamma_i^{\rm req}N_0B_i}{g_{ij}}.
]

如果 UAV (i) 的一个 packet 必须被集合 (\mathcal R_i) 中所有节点收到，那么：

# [ \boxed{ P_{{\rm comm},i}^{\min}

\max_{j\in\mathcal R_i}
P_{ij}^{\rm req}.
}
]

也就是**最差必要 U2U 链路决定广播功率**。

这不是 heuristic，是当前通信模型下直接反解出来的结果。

------

# 3. 但不要直接用“所有邻居”作为 (\mathcal R_i)

这里很容易犯一个新错误。

(\mathcal R_i) 应该是：

[
\boxed{\text{当前协议语义真正要求送达的 receiver set}}
]

而不是几何邻居全集。

否则 L0 会人为保留本来就没有必要可靠送达的链路，回收不到通信功率。

反过来，也不能只保 owner，如果其他 UAV 当前确实依赖这个 Token。

所以最好把当前 transport layer 已经生成的：

- sender identity；
- receiver requirement；
- packet；
- epoch/digest

直接作为 L0 输入。

这样 L0 不改变协议，只优化 RF margin。

------

# 4. 得到的 slack 才是有意义的

定义：

# [ \boxed{ s_i^{\rm comm}

## P_{{\rm comm},i}^{\rm actor}

P_{{\rm comm},i}^{\min}.
}
]

总通信余量：

# [ S_{\rm comm}

\sum_i(s_i^{\rm comm})_+.
]

对应新的 sensing budget：

# [ \boxed{ b_i'

# 1-P_{{\rm comm},i}^{\min}

b_i+s_i^{\rm comm}.
}
]

然后**结构、几何完全不动**，重新求：

# [ \gamma_{P,\rm after}^{\star}

\gamma^\star(A,b').
]

与原来的

# [ \gamma_{P,\rm before}^{\star}

\gamma^\star(A,b)
]

比较。

------

# 5. 这一轮真正应该看的不是平均 sensing 提升，而是“困难 epoch 被解释掉多少”

尤其针对 D0.93-E 的 52 个 `certified escalate` epoch。

建议分成：

[
\boxed{
\gamma_{\rm before}^{L}>1
}
]

经过 L0 后重新构造：

[
[\gamma_{\rm after}^{L},\gamma_{\rm after}^{U}].
]

然后统计三类转移：

| 原状态   | L0 后     | 含义                                 |
| -------- | --------- | ------------------------------------ |
| escalate | stay      | **纯通信功率错配**                   |
| escalate | ambiguous | 通信余量解释一部分                   |
| escalate | escalate  | **真正的 sensing/structure deficit** |

这张表比只报

[
\Delta worst
]

更有诊断价值。

------

# 6. 可以定义一个没有调参的“communication-recoverable deficit ratio”

对于原来

[
G_P=(\gamma_P^\star-1)_+,
]

经过 L0 后：

# [ G_{P,0}

(\gamma_{P,0}^\star-1)_+.
]

定义：

# [ \boxed{ R_{\rm comm}

\frac{
G_P-G_{P,0}
}{
G_P+\varepsilon
}.
}
]

其解释非常直接：

- (R_{\rm comm}=0)：通信功率不是问题；
- (R_{\rm comm}=1)：原 capability deficit 全部是通信功率留多导致的；
- (0<R_{\rm comm}<1)：部分解释。

这比说“通信功率降低了 20%”更重要，因为它直接回答：

> **通信资源错配贡献了多少 sensing capability deficit？**

------

# 7. 这里还有一个很重要的理论性质

之前已经证明：

[
b'\succeq b
\Rightarrow
\gamma^\star(A,b')
\le
\gamma^\star(A,b).
]

而 L0 恰好给出：

[
b_i'=1-P_{{\rm comm},i}^{\min}
\ge
1-P_{{\rm comm},i}^{actor}=b_i.
]

因此直接得到：

[
\boxed{
\gamma_{P,0}^\star
\le
\gamma_P^\star.
}
]

也就是说，只要 L0 **不改变通信可行语义**，它对于 sensing capability 是严格 no-harm 的。

这条链非常干净：

[
P_{\rm comm}^{min}\le P_{\rm comm}^{actor}
]

[
\Downarrow
]

[
b'\ge b
]

[
\Downarrow
]

[
\gamma^\star(A,b')
\le\gamma^\star(A,b).
]

它可以作为 L0 的一个 Proposition。

------

# 8. 但是要注意：这个结论依赖当前通信模型

当前总纲里的 U2U 模型是活跃发送者**正交平分带宽**，所以固定 active set 后，一个 transmitter 降功率不会提高其他链路的干扰。

因此这里的 per-Tx inverse power control 很干净。

如果以后扩展成：

- 同频复用；
- communications interference；
- sensing→communication leakage；
- joint beamforming；

那么

[
P_i^{\min}
]

不再能逐 UAV 独立求。

会变成耦合的 SINR power-control problem：

# [ \Gamma_{ij}

\frac{P_i g_{ij}}
{N_0+\sum_{k\ne i}P_kg_{kj}}.
]

那时可以用标准干扰函数/固定点方法，而不能继续套现在这个闭式。

所以论文应明确：

> L0 闭式最小功率成立于当前 orthogonal-U2U transport model。

这反而是尊重基本通信原理。

------

# 9. 不要把 L0 包装成主要创新

L0 本质上是：

[
\text{link-margin-aware minimum communication power}.
]

这个单独拿出来并不新。

它真正的作用是让你的主创新更加可信：

[
\boxed{
\text{先回收通信 slack}
\rightarrow
\text{再认证 sensing capability}
\rightarrow
\text{仍不足才升级结构}.
}
]

这使得所谓的：

> minimum-necessary-layer activation

真正成立。

否则你会面临一个非常合理的审稿质疑：

> “为什么结构重构之前不先把过度分配给通信的功率拿回来？”

L0 正好堵住这个漏洞。

------

# 10. 我会把现在的体系从四层再整理成“资源阶梯”

以后不要简单写：

[
communication\rightarrow power\rightarrow structure\rightarrow geometry.
]

更准确地说是：

[
\boxed{
\begin{aligned}
L0:;&
\text{communication slack recovery}\
&\min P_{\rm comm}
\quad
\text{s.t. transport semantics unchanged}
\[1mm]
L1:;&
\text{sensing capability allocation}\
&\gamma_P^\star(A,b')
\[1mm]
L2:;&
\text{structure capability expansion}\
&\min_S\gamma_S^\star
\[1mm]
L3:;&
\text{geometry capability expansion}\
&\min_x\gamma_G^\star
\end{aligned}
}
]

这形成一个很清楚的原则：

[
\boxed{
\text{先使用成本最低、最可解析的自由度；
只有其被证明耗尽后才打开更昂贵自由度。}
}
]

------

## 11. L0 的 Gate 我建议提前冻结

这一轮先不要改 Actor，也不要重训。

固定 D0.93-E 的 trace，只跑审计。

至少输出：

1. 

[
P_{\rm comm}^{actor},
P_{\rm comm}^{min},
S_{\rm comm}
]

1. L0 前后：
   [
   \gamma^{L},\gamma^{U}
   ]
2. 三态迁移矩阵：
   `stay / ambiguous / escalate`
3. 52 个原 escalate epoch 中，有多少变成：
   `stay / ambiguous / still escalate`
4. capability deficit recovery：
   [
   R_{\rm comm}
   ]

如果结果是：

> 52 个 escalate 里 30 个被 L0 救回来，

那么之前主要问题其实不是 structure。

如果只有：

> 52 个里 1–2 个变化，

也非常有价值：

[
\boxed{
\text{communication slack 不是主因，结构层升级得到更强因果依据。}
}
]

**正结果和负结果都能推动架构收敛。**

所以我建议现在做 L0，而且先把它作为一个**严格冻结协议语义的诊断 Gate**，而不是直接接进 live deployment。通过之后再决定是否正式成为最前面的在线资源回收层；随后再进入 D0.93-A2 的双侧 PWL capability certificate。
