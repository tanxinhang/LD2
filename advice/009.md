是的。按你现在重新设定的目标，**D0.95 不能再视为“接近完成”，而应视为第一代解析控制器**。当前 8/8 是 `worst=0.662、QoS feasible rate=0.65`，而同几何 relaxed ceiling 达到 `0.868`，说明系统还有明显算法 headroom，并非只能靠统计或瞬态修补。

更重要的是，当前 L1 在**给定结构和几何以后已经是精确 max-min LP**；真正偏弱的是外层：live L2 还是近似排名，L3 还是**单帧、一次梯度、归一化步长**。 所以接下来如果目标是

[
\boxed{\text{worst}\rightarrow0.70\sim0.80,\qquad
P_{\rm QoS}\ge 0.80}
]

我建议进行一次真正的算法升级，而不是继续 D0.96 式修补。

# 1. 先明确：0.662 → 0.8 并没有想象中那么远

当前

[
P_D=Q!\left(Q^{-1}(10^{-3})-\sqrt D\right).
]

按这个映射粗略换算：

| (P_D)      | 所需 (D) |
| ---------- | -------- |
| 0.60       | 11.18    |
| 当前 0.662 | 12.31    |
| 0.70       | 13.07    |
| 0.75       | 14.17    |
| 0.80       | 15.46    |

也就是说，从代表性的 `0.662 → 0.70`，Deflection 只需要约 **+6%**；到 `0.80` 大约需要 **+26%**。

而当前 relaxed ceiling 与部署解之间远不止 26% 的空间。文档的 waterfall 是：

[
0.31\rightarrow0.675\rightarrow0.700\rightarrow0.706\rightarrow0.868.
]

所以我认为：

> **worst 0.70 很现实，0.75 应该成为主攻目标，0.80 不应现在排除。**

真正的问题是现在的算法没有很好地把 relaxed headroom 转换成可执行几何。

------

# 2. 最大的问题其实是 L3：当前是一阶反应式控制，而不是规划

当前 L3 本质上是：

[
g_k=\sum_q\lambda_qp_{kq}\nabla_{x_k}a_{kq},
]

然后

# [ \Delta x_k

-\text{step}\frac{g_k}{|g_k|}.
]

这个设计安全、简单，但为了冲到 0.7–0.8 有三个明显问题。

第一，**它只看当前一帧**。UAV 可能需要连续 5–20 帧先经过一个暂时收益较低的位置，才能形成好的 Tx-target-Rx 双基地几何；单步 gradient descent 看不到这种收益。

第二，归一化

[
g/|g|
]

把梯度大小全部扔掉了。一个非常确定的强改进方向和一个接近平坦区域的弱方向，最后都移动相同距离。

第三，

[
\sum_q\lambda_q\nabla a_{kq}
]

容易产生**目标间梯度抵消**。例如 UAV (k) 对目标 1 应向东，对目标 2 应向西，最后可能几乎不动。

所以我认为下一版最值得做的不是“更好的 gradient”，而是：

[
\boxed{\textbf{Horizon Joint Structure-Power-Geometry Planner}}
]

------

# 3. 主算法建议：Horizon Primal-Dual MPC

把现在的：

[
L2_t\rightarrow L1_t\rightarrow L3_t
]

升级成预测未来 (H) 帧的：

[
\boxed{
{S_{t:t+H},P_{t:t+H},X_{t:t+H}}
}
]

联合规划。

不要求直接解完整 MINLP，而采用：

[
\boxed{
\text{结构候选}
\leftrightarrow
\text{精确 L1}
\leftrightarrow
\text{几何 SCP}
}
]

交替优化。

### 核心目标也要变

不要继续只优化瞬时

[
\max\min_qD_q(t).
]

改成预测窗口的 tail objective：

[
\max_{\mathbf X,\mathbf S,\mathbf P}
\quad
\eta
-\beta
\sum_{h=1}^{H}\sum_q
[D_{\rm tar}-D_{q,t+h}]*+^2
-\mu C*{\rm move}
-\xi C_{\rm switch},
]

其中

[
\eta
\le
\frac1H\sum_{h=1}^{H}D_{q,t+h},
\qquad\forall q.
]

目标值直接设成：

[
D_{\rm tar}=D(P_D=0.75)\approx14.17
]

第一阶段，不再以 `0.60` 为 satisficing target。

等 0.75 稳定以后再把：

[
D_{\rm tar}:14.17\rightarrow15.46
]

推到 (P_D=0.80)。

这相当于 **QoS curriculum / continuation**，比一开始硬逼 0.8 更稳定。

------

# 4. 几何层建议从 Gradient Descent 升级成 SCP / Trust-Region

这是我认为最可能直接提高 worst 的算法修改。

在当前位置 (x^{(r)}) 附近建立：

[
a_{ijq}(x+\Delta x)
\approx
a_{ijq}(x)
+
\nabla a_{ijq}^{T}\Delta x
+
\frac12
\Delta x^TH_{ijq}\Delta x.
]

然后每轮求一个 trust-region 子问题：

[
\max_{\Delta x,p,t}
\quad t
]

subject to

[
D_{q,h}(\Delta x,p)\ge t,
]

[
|\Delta x_{k,h}|\le d_{\max},
]

以及边界、角色、通信等约束。

得到：

[
\Delta X^{(r)}
]

后重新计算真实物理量，再决定接受还是缩小 trust region。

即：

[
X^{(r)}
\rightarrow
\text{linear/quadratic model}
\rightarrow
\Delta X
\rightarrow
\text{exact physics}
\rightarrow
X^{(r+1)}.
]

这比当前：

[
-\frac{\nabla\gamma}{|\nabla\gamma|}
]

强很多。

特别是当前文档已经指出 DD gate：

[
1[g_{dd}\ge g_{\min}]
]

会引起支撑不连续，因此更适合使用 **support-aware trust region**：

[
g_{dd}-g_{\min}\ge m_{\rm safe}
]

时使用连续梯度；靠近 DD 边界时，把“跨 support”作为离散候选，而不是硬用梯度穿过去。

------

# 5. 再加一个关键模块：Target Responsibility Assignment

这个我反而觉得可能非常重要。

不要让每架 UAV 同时响应：

[
\sum_q\lambda_q\nabla a_{kq}.
]

先解决一个小规模责任分配问题：

[
z_{kq}\in[0,1],
]

其中 (z_{kq}) 表示 UAV (k) 当前主要负责改善目标 (q)。

定义预测收益：

# [ G_{kq}

## \lambda_q \cdot b_k \cdot |\nabla_{x_k}a_{kq}|

## c_{\rm move}d_{kq}

c_{\rm conflict}.
]

求：

[
\max_z
\sum_{k,q}z_{kq}G_{kq},
]

并限制：

[
\sum_qz_{kq}\le1,
]

以及每个 weak target 至少获得若干 UAV 支持。

于是原来的：

[
\text{所有 UAV 都听同一组 }\lambda_q
]

变成：

[
\boxed{
\lambda_q
\rightarrow
\text{目标紧迫度}
\rightarrow
\text{UAV responsibility auction}
\rightarrow
\text{目标专属几何运动}
}
]

这样可以显著减少**梯度互相抵消和所有 UAV 扎堆同一个最差目标**。

而且这个模块非常适合分布式实现：

- target owner 广播 (\lambda_q)；
- UAV 本地算 (G_{kq})；
- 发送 Top-1/Top-2 bid；
- owner 做 auction；
- 只交换极少量标量。

这比再做一个神经网络结构头更有理论和工程意义。

------

# 6. L2 也应该升级，但不是简单 priced Top-K

当前 live L2 还是 P0 per-watt ranking；离线 `priced_structure.py` 才做 owner+TX 重分配。

如果只是把 priced Top-K 接进 live，我预计最多主要吃：

[
0.675\rightarrow0.700/0.706
]

这部分空间。

**单独靠它很难把 0.662 拉到 0.8。**

更强的 L2 应该做：

[
\boxed{
\text{price-weighted joint role/owner/support assignment}
}
]

而不是逐目标独立 Top-K。

可以写成：

## [ \max_z \sum_{i,j,q} z_{ijq} \lambda_q \hat a_{ijq} \hat p_{iq}

\rho C_{\rm switch}(z)
]

subject to：

- TX/RX 半双工；
- 每目标唯一 owner；
- 每 RX 容量；
- 每 TX support 数量；
- 通信可达性；
- RF budget。

这本质上是一个小型广义分配问题。

部署时不要 MILP，可以用：

[
\boxed{\text{dual decomposition + distributed auction}}
]

求近似解。

所以新 L2 不应该再叫“ranking”，而应该成为：

> **Distributed Price-Based Role–Owner Auction**

这是一个可以真正写成方法贡献的东西。

# 7. 最关键的结构变化：L1 不再是“最后补功率”，而是整个规划器的 inner solver

目前：

[
\text{structure}
\rightarrow
\text{power LP}.
]

新方案应该变成：

# [ \boxed{ F(S,X)

\max_P\min_qD_q(S,X,P)
}
]

即直接把 L1 看作一个 value function。

结构层优化：

[
\max_SF(S,X)
]

几何层优化：

[
\max_XF(S,X)
]

其梯度仍然可以由当前对偶价格提供：

# [ \nabla_XF

\sum_q
\lambda_q^\star
\sum_i
p_{iq}^\star
\nabla_Xa_{iq}.
]

这样就不是“L1/L2/L3 三个独立启发式模块”，而变成：

[
\boxed{
\text{一个 bilevel primal-dual optimization}
}
]

这会让整篇工作的理论主线也明显更强。

# 8. 如果目标真的是 worst≈0.8，还应该加入 CVaR / shortfall，而不是只优化 max-min

纯 max-min 有一个问题：

一个目标从：

[
0.40\rightarrow0.50
]

可能吸走大量资源，而其他 7 个目标全部已经 0.78。

如果最终评价真正关注：

[
P_{\rm QoS}\ge0.8,
]

就应该显式优化**失败尾部**。

例如定义：

[
\ell_q=[D_{\rm tar}-D_q]_+.
]

使用：

[
\min
\operatorname{CVaR}_{\alpha}(\ell_q)
]

或者更简单地：

[
\min
\left[
\max_q\ell_q
+
\beta\frac1{|\mathcal W|}
\sum_{q\in\mathcal W}\ell_q
\right].
]

这里 (\mathcal W) 就是 bottom-3。

因此可以同时兼顾：

[
worst,\quad weak3.
]

我建议主目标直接改成：

# [ \boxed{ J

## D_{\min} + \beta D_{\rm weak3}

\mu,\mathrm{CVaR}(\text{shortfall})
}
]

而不是继续让三地板只作为 feasibility checks。

# 9. 一个更激进但值得测试的版本：两时间尺度角色调度

如果上面的联合 MPC 仍然卡在 `0.70–0.73`，我会开始怀疑**当前每帧固定 TX/RX role 本身限制了可达域**。

可以把一个 0.1 s frame 分成两个 sensing mini-slot：

[
\theta,\quad1-\theta.
]

UAV 可以：

- slot A 做 TX；
- slot B 做 RX。

瞬时仍满足半双工，但帧平均上实现 time-sharing。

这样：

# [ D_q

\theta D_q^{(A)}
+
(1-\theta)D_q^{(B)}.
]

这相当于扩大原来的离散结构凸包。

它可能比允许 full duplex 更合理，也保持实际半双工硬件约束。

不过当前 `single→duplex` 只有 `+0.006`，所以**这不是第一优先级**；应该等联合几何规划跑完以后再决定。
