这轮结果非常关键，因为它把之前混在一起的两个问题拆开了：

- **QoS feasible rate 问题基本已经解决**：20/20，单侧 Wilson LCB 0.881；
- **性能上限问题还没有解决**：live `worst=0.671`，距离你真正想要的 0.70–0.80 还有明显空间。

因此我会正式改变 D1.x 的优先级：**接下来不应先做 joint auction，而应先修改 L1/L3 的优化逻辑。**

不要把验收标准偷偷改高。

### QoS tolerance：建议长期加入

这个必须修。

像

[
0.6-1.11\times10^{-16}
]

被判断为失败，本质是评估器 bug，而不是算法失败。

[

```python
qos_eval_tol = 1e-6
```

`1e-6` 对 (P_D\in[0,1]) 的性能尺度完全可以忽略，却远高于 binary floating error。

不过最好同时输出：

```text
raw_worst
raw_weak3
raw_steady

worst_slack  = raw_worst  - 0.60
weak3_slack  = raw_weak3  - 0.70
steady_slack = raw_steady - 0.80

qos_feasible_tol
```

这样不会出现“用了 tolerance 所以隐藏真实低于门限”的质疑。

# 2. 这轮其实暴露了一个更重要的算法问题：Gauge 本来就会把性能钉在门限附近

这是下一步我最想改的地方。

现在 capability gauge 解的是：

[
\min \gamma
]

subject to

[
P_D^{\rm worst}\ge0.61,
\quad
P_D^{\rm weak3}\ge0.71,
\quad
P_D^{\rm steady}\ge0.81.
]

它解决的问题实际上是：

> **“最低要花多少资源才能满足任务？”**

而不是：

> **“满足任务以后，还能把 worst 推多高？”**

所以你发现很多 seed 被钉在：

[
P_D^{\rm worst}\approx0.60
]

其实不是偶然。

这是 **satisficing optimizer 的必然行为**。

这也是为什么：

- gauge：QoS 强；
- max-min：worst 强；
- 你现在的 penalty hybrid：两边都没有完全获得。

# 3. 下一步我最推荐的算法不是现在的 hybrid，而是 Lexicographic Gauge → Max-Min

这个区别非常重要。

你目前的 hybrid 更类似：

[
J=
J_{\rm maxmin}
-\rho,\mathrm{QoSViolation}.
]

这种 penalty blending 会发生权衡。

我建议改成真正的**两阶段字典序优化**。

------

## Stage A：先证明 QoS 可行

运行现有 gauge：

# [ \gamma^\star

\min\gamma.
]

如果：

[
\gamma^\star\le1,
]

说明三地板可以满足。

到这里 gauge 的任务就结束了。

**不要直接拿 gauge 的功率解执行。**

------

## Stage B：在“不允许破坏 QoS”的条件下继续最大化 worst

重新解：

[
\boxed{
\max_{p,t}\ t
}
]

subject to

[
D_q(p)\ge t,\qquad\forall q,
]

同时保留完整 QoS 硬约束：

[
P_D^{\rm worst}\ge0.61,
]

[
P_D^{\rm weak3}\ge0.71,
]

[
P_D^{\rm steady}\ge0.81,
]

以及：

[
\sum_qp_{iq}=b_i,\qquad
p_{iq}\ge0.
]

也就是：

[
\boxed{
\text{QoS feasibility first}
\succ
\text{worst maximization second}.
}
]

不是：

[
\text{QoS}+\alpha\text{worst}.
]

------

# 4. 为什么我认为这一步应该先于 Horizon L3

因为它几乎是一个“免费”的算法改进。

现有结果已经告诉我们：

[
\text{Gauge QoS}\approx0.90
]

但

[
\text{MaxMin worst potential}\approx0.85.
]

这意味着两个优化器分别占据了两个 Pareto 极端。

我们现在根本不应该在它们之间做 weighted average，而应该问：

> 在 Gauge 已经找到可行域以后，MaxMin 能否在这个可行域内部继续优化？

理论上它应该满足：

[
\text{QoS}*{lex}
\ge
\text{QoS}*{gauge},
]

同时：

[
D_{\min,lex}
\ge
D_{\min,gauge}.
]

至少在同一几何/结构下，**新的解不应该比 gauge 更差**，因为 gauge 解本身就是 Stage-B 的一个可行点。

这比 penalty hybrid 强得多。
