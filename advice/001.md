我已经按 **代码、系统模型、配置、物理层公式、通信协议、优化器、Architecture-v2 测试以及最近提交历史** 对 `tanxinhang/LD2` 的 `codex/architecture-v2` 做了一轮交叉审计。审计基准是当前分支头 **`56e8e2c1`，2026-08-26**。这一提交已经删除了 congestion-relief、V3 dual-priced L2 等被实验否定的机制，并修复 RNG、Wilson、退化情形等问题，这说明当前分支的方向已经从“不断加模块”开始转向“删掉不能成立的机制”，这一步是正确的。

但我的结论是：

> **现在不应该继续直接增强 Phase A/B/C、继续堆 MARL、repair、bargaining 或新的启发式。**
>
> 当前剩下的主要问题已经不是“算法性能不够”，而是 **系统身份、物理时间尺度、OTFS DD 语义、通信资源语义、分布式信息边界和优化理论之间还没有完全闭合**。
>
> 如果现在继续优化，很容易出现“数字继续上升，但理论可信度反而下降”。

我建议把系统进一步收敛到一个新的核心：**Capability-Margin Driven Distributed ISAC（能力裕度驱动的分布式 ISAC）**。这比现在的“几何启发式 + LP + repair”更统一，也更有可能形成真正的论文创新。

# 二、最先要纠正的不是算法，而是“当前系统到底是什么”

这是目前我认为最高优先级的问题。

文档把当前系统描述成 U2U-only、严格 joint RF power、分布式局部信息；但 `Params` 默认值中仍存在诸如 `ground_communication_enabled=True`、`joint_isac_power_enabled=False`、`distributed_coordination_use_local_belief_targets=False` 之类与论文“当前系统”语义不一致的默认路径。

这不意味着每次实验一定错——runner 可能 override——但意味着：

> **“代码默认系统” ≠ “文档系统” ≠ “某个实验 runner 实际系统”。**

这是危险的。

我建议立即建立唯一的：

```text
config/canonical_post_g2.yaml
```

或者更强一点：

```text
system_manifest.yaml
```

正式论文结果只能由这个 manifest 启动，并强制包含：

`ground=false`、`strict_no_ground_fusion=true`、`joint_rf_power=true`、`distributed_local_belief=true`、OTFS numerology、sensing duration、comm duration、detector convention、power model version、fusion covariance assumption、commit SHA、seed scheme。

当前 `CURRENT_SYSTEM_MODEL.md` 仍保留已经被最新 commit 删除的 V3 描述，这已经证明“代码—数学文档”发生漂移。

# 三、目前最严重的物理问题：sensing 的两个“时钟”没有统一

当前参数大致是

[
N=16,\qquad
T_{\rm sym}=\frac{1}{15{\rm kHz}},
]

所以单个 sensing frame 的有效时间约为

[
T_{\rm sense}
=============

# NT_{\rm sym}

\frac{16}{15000}
\approx1.067{\rm ms}.
]

而环境 step 是

[
\Delta t=0.1{\rm s}=100{\rm ms}.
]

当前 deflection 路径使用的是近似 **一个 CPI / 一个 sensing frame** 的观测能量，而 battery 路径却存在

[
E_{\rm sense}=P_{\rm sense}\Delta t
]

这样的 100 ms 计费方式。

两个时钟相差大约

[
\frac{100}{1.067}\approx93.75.
]

这里无论哪个解释都存在问题。

如果一 step **只发一个 OTFS sensing frame**，应该：

[
E_s=P_sT_{\rm sense}.
]

如果 UAV 在整个 100 ms 内持续进行 sensing，那么就不应该只在 deflection 中算一次 CPI，而应该考虑大约 94 个 frame 的 coherent/non-coherent integration 规律。

所以现在不能简单修一个乘数，应该正式定义：

[
T_{\rm slot}
============

T_s+T_c+T_{\rm idle}
]

或者如果 communication/sensing 可重叠：

[
T_s,;T_c,;T_{s\cap c}
]

并分别定义**瞬时 1 W 功率约束**和**slot energy 约束**。

这是一个典型的“数值可能跑得很好，但物理闭环尚未闭合”的问题。

# 四、Doppler 公式确实有一个符号问题，而且 Phase C 会把它从 latent bug 变成 P0

当前 `compute_doppler()` 的 receiver 项值得修正。

双基地总路程

[
R
=

|\mathbf x_q-\mathbf x_i|
+
|\mathbf x_j-\mathbf x_q|.
]

定义

[
\mathbf u_{iq}
==============

\frac{\mathbf x_q-\mathbf x_i}{R_{iq}},
\qquad
\mathbf u_{qj}
==============

\frac{\mathbf x_j-\mathbf x_q}{R_{jq}}.
]

则

[
\dot R
======

(\mathbf v_q-\mathbf v_i)^T\mathbf u_{iq}
+
(\mathbf v_j-\mathbf v_q)^T\mathbf u_{qj}.
]

如果采用“总传播距离缩短对应正 Doppler”的 convention，

[
\nu=-\frac{f_c}{c}\dot R,
]

因此

[
\boxed{
\nu
===

\frac{f_c}{c}
\left[
\mathbf v_i^T\mathbf u_{iq}
---------------------------

\mathbf v_j^T\mathbf u_{qj}
+
\mathbf v_q^T(\mathbf u_{qj}-\mathbf u_{iq})
\right].
}
]

当前 receiver 项实际上用了相反符号。

以前这个问题还可以称为 latent，因为很多路径只看 (|\nu|)。但是 `THREE_PHASE_POLICY_DESIGN` 的 Phase C 已经准备利用 signed Doppler 做方向控制。

所以：

> **Phase C 现在不能直接继续。先把 Doppler convention + 单元测试锁死。**

最简单的 physics contract：

“Tx/target 静止，Rx 朝目标飞行 ⇒ positive Doppler”。

# 五、当前 OTFS DD 模型还没有真正体现“OTFS-specific sensing”

现在 `compute_bin_mismatch()` 计算

[
l=\tau M\Delta f,
\qquad
k=\nu NT_{\rm sym},
]

然后只取离最近整数 bin 的 fractional offset，再用 sinc 得到 `g_delay`、`g_doppler`。

这里有两个问题。

第一个问题是 **alias / unambiguous support**。

仅判断“离整数 bin 多远”不够。一个实际已经超出 unambiguous delay/Doppler region 的目标，也可能因为 alias 后恰好接近一个整数位置而得到

[
g_{dd}\approx1.
]

所以应该拆成：

[
I_{\rm support}(\tau,\nu)
]

和

[
A(\Delta\tau,\Delta\nu).
]

第二个问题更重要。

当前 `g_dd` 是 sinc **幅度**。如果 matched-filter mean 被缩放 (g_{dd})，那么 deflection 应该近似按平方缩放：

[
D
=

\frac{|\mu_1-\mu_0|^2}{\sigma^2}.
]

因此应该是

[
\boxed{
D_{ijq}^{\rm phys}
==================

I_{\rm support}
|A(\tau,\nu)|^2
D_{ijq}^{(0)}
}
]

而不是主要采用

[
g_{dd}\ge g_{\min}
]

之后保持原 deflection。

这也恰好与近年的 ISAC waveform 研究方向一致：研究开始显式分析和设计**连续 delay-Doppler ambiguity function**，而不是只做整数 bin 是否命中。2025 年已有工作系统比较 OTFS 等波形的连续 ambiguity-function 特性，并强调 normalized delay-Doppler response；连续 Doppler region 的 ambiguity 优化也成为明确研究问题。([arXiv][1])

这反而给这个系统提供了一个增强 OTFS 特色的机会。

# 六、Phase A 当前的理论需要推翻一部分

这是这轮审计里另一个很关键的发现。

当前 Phase A 基本思想是：

[
G_{ijq}=R_{iq}^2R_{jq}^2
]

找最大的 product，也就是 weakest target，然后让某个 UAV 向它靠近，并把它解释成“steepest descent”。

**“找 weakest target”这个直觉可以保留，但“这是 steepest descent”不成立。**

在最简单模型下

[
D_q
===

\frac{C_qP}{R_{iq}^2R_{jq}^2}.
]

若只移动 transmitter (i)：

[
\frac{\partial D_q}{\partial R_{iq}}
====================================

-\frac{2C_qP}
{R_{iq}^3R_{jq}^2}.
]

更干净的是：

[
\nabla_{\mathbf x_i}\log D_q
============================

\frac{2}{R_{iq}}\mathbf u_{iq}.
]

所以“最大的 (R_i^2R_j^2)”意味着 **当前 D 最差**，却不等于“该 UAV 的可执行动作具有最大 marginal gradient”。

这两个问题不能混在一起：

[
\text{who is weakest}
\neq
\text{where should this UAV move}.
]

而且原文例子中 278 m 降到 200 m：

[
\left(\frac{200}{278}\right)^2
\approx0.518,
]

对应约 **48.2%** 的单腿 squared-range factor 降低，不是 33%。

# 七、`R_crit = 320 m` 也应该升级：这里其实有一个很漂亮的理论结构

固定地说：

> “Tx/Rx 都进入目标 320 m 内，就具备 sensing capability”

不是真正的双基地 sensing invariant。

从

[
D_q
===

\frac{C_qP}
{R_{iq}^2R_{jq}^2}
]

以及所需检测概率反推最低 deflection。

当前 detector 使用类似：

[
P_D
===

Q\left(
Q^{-1}(P_{FA})
-\sqrt{c_{\rm det}D}
\right).
]

于是给定目标 (P_D^\star)：

[
\boxed{
D_q^{\rm req}
=============

\frac{
\left[
Q^{-1}(P_{FA})
--------------

Q^{-1}(P_D^\star)
\right]^2
}
{c_{\rm det}}
}
]

。

因此真正的几何条件是

[
R_{iq}^2R_{jq}^2
\le
\frac{C_qP}{D_q^{\rm req}}.
]

注意，这不是“两个 320m 圆”。

它是一个 **product-range capability condition**，从几何上更接近 **Cassini-type capability surface**。

这个东西我认为值得直接升级成论文概念：

> **Bistatic Capability Margin / Cassini Capability Margin**

定义

[
m_q
===

\log\frac{D_q}{D_q^{\rm req}}.
]

于是：

[
m_q>0
]

就是达到 sensing QoS，

[
m_q=0
]

就是 detection capability boundary，

[
m_q<0
]

就是不可满足区域。

这样原先人为的 `320m`、worst-target、deflection、几何运动和 sensing QoS 会第一次被同一个量统一起来。

# 八、建议彻底重写 Phase A：不再追 range product，而追“最坏任务能力裕度”

这一步可以把目前的启发式提升成一个真正有理论依据的算法。

对于 critical targets (\mathcal Q_c)，慢时间尺度位置控制改为：

[
\begin{aligned}
\max_{{\mathbf v_i},\xi}\quad
&\xi\
{\rm s.t.}\quad
&
\nabla_{\mathbf x}m_q^T\mathbf v
\ge \xi,
\quad
q\in\mathcal Q_c,\
&
|\mathbf v_i|*2\le v*{\max},\
&
\text{collision/separation/flight constraints}.
\end{aligned}
]

固定当前点进行一阶近似后，这本质上可以做成一个很小的 **SOCP / convex subproblem**。

意义非常明确：

[
\boxed{
\text{每一步都尽可能提高最危险目标的 capability margin}
}
]

而不是：

[
\text{找最远目标然后飞过去}.
]

这既符合感知物理，又保留分布式实现空间。

# 九、Phase B 可以保留，但要从“饱和功率搬运”升级成“certificate-preserving power release”

Phase B 的直觉本身是好的：

> 已经很强的目标不用继续浪费 sensing power。

但是“saturated target 向 bottleneck target 转功率不会伤害性能”不是无条件成立。

如果当前固定结构满足

[
D_q=\sum_e a_{eq}p_e,
]

从 donor (s) 的某个 edge (e) 回收功率 (\Delta p)，要保证

[
D_s-a_{es}\Delta p
\ge D_s^{\rm safe}.
]

即

[
\boxed{
\Delta p
\le
\frac{D_s-D_s^{\rm safe}}{a_{es}}.
}
]

因此不要称“saturation release”，我更建议叫：

> **Capability-Certificate Preserving Reallocation**

只释放**可证明不会破坏 detection certificate 的 slack**。

这样 Phase B 不再是 heuristic，而有一个非常短且干净的 proposition。

当前 fixed-structure max-min power LP 本身其实是系统里比较扎实的一部分：在结构固定、deflection 对功率线性的假设下，它是一个标准 LP，可以得到全局最优。

所以这部分应该作为**数学主干保留**，不要继续换复杂 RL。

# 十、L0 的 bandwidth optimizer 有一个实质 KKT 问题

当前 analytical communication power 基本使用：

[
P_i(B)
======

\frac{N_0B}{g_i}
\max\left{
\gamma_{\min},
2^{r_i/B}-1
\right}.
]

这个模型本身没问题。

问题是 optimizer 对 marginal derivative 的处理。

令

[
a_i=r_i\ln2,\qquad
c_i=N_0/g_i.
]

rate-limited branch：

[
f_i(B)
======

c_iB(e^{a_i/B}-1)
]

的导数为

[
f_i'(B)
=

c_i
\left[
e^{a_i/B}
\left(1-\frac{a_i}{B}\right)-1
\right]
<0.
]

而 SNR-floor branch：

[
g_i(B)=c_i\gamma_{\min}B
]

导数为正。

当前实现类似把两个 derivative 直接 `max()`，但：

[
\frac{d}{dB}\max(f,g)
\neq
\max(f',g').
]

分支必须由 **函数值哪个 active** 决定。

还有一个更有意思的结论。

每个用户的独立最优 crossover：

[
\boxed{
B_i^{\rm cross}
===============

\frac{r_i}
{\log_2(1+\gamma_{\min})}.
}
]

如果

[
B_{\rm total}
\ge
\sum_iB_i^{\rm cross},
]

最佳方案不是强迫“no-waste bandwidth”把所有 20 MHz 用满，而是：

[
B_i=B_i^{\rm cross}
]

并允许剩余 bandwidth idle。

因为超过 crossing 后，继续增加 bandwidth 会由于最低 SNR 约束导致功率**线性增加**。

所以：

> **“带宽不能浪费”在这个模型下不是数学定理，甚至可能增加 RF power。**

这应该直接纠正。

# 十一、通信协议还有一个被算法抽象掩盖的问题：一个 broadcast 不能有多个物理码长

当前 `transmit_broadcast()` 对不同 receiver 分别计算 SNR，然后分别求 receiver-specific Shannon rate / FBL blocklength，最后 sender 按最大 serialization time 记一次 airtime。

从软件抽象上方便，但从物理层看：

> 一个 sender 发出的一个 broadcast packet，本质上只能有一个实际 codeword。

不能：

[
n_{i\to j_1}=100,\qquad
n_{i\to j_2}=180
]

却仍称为同一次 atomic broadcast。

正确方案是：

[
n_i
===

\min\left{
n:
\max_{j\in\mathcal R_i}
\epsilon(n,k,\gamma_{ij})
\le\epsilon^\star
\right}.
]

也就是由 intended receiver set 中最弱链路确定 common codeword。

或者系统显式选择 receiver subset：

[
\mathcal R_i^\star
]

然后剩下的信息走下一轮/multi-hop。

这反而可以形成一个很好的 communication–sensing 联合优化点：

[
\text{“应该通知哪些邻居”}
+
\text{“需要多少 blocklength”}
]

由 sensing decision value 决定。

已有的 finite-blocklength normal approximation 模块是可以利用的，不需要自己造通信可靠性模型。

# 十二、真正值得做的新创新：不要传“完整状态”，而传“足够保证决策不变的信息”

这一点我认为比继续 MAPPO、attention 或 bargaining 更有价值。

最近 2025–2026 年，多 UAV/ISAC 已经存在 trajectory + beamforming/resource optimization、task-oriented UAV communication、task-oriented SC3 closed-loop 等路线；单纯再做“联合轨迹+资源+MARL”已经很拥挤。([开放获取期刊目录][2])

甚至 2026 年 8 月已经出现新的 hierarchical/cell-free multistatic ISAC 架构，显式讨论分布式接收机参与 sensing 与通信开销。([arXiv][3])

所以我更推荐：

## **Decision-Sufficient Communication**

假设本地需要在候选 edge 中选择

[
e^\star=\arg\max_es_e(z).
]

第一名与第二名的 gap：

[
\Delta
======

## s_{e^\star}(z)

\max_{e\ne e^\star}s_e(z).
]

通信压缩后获得 (\hat z)。若能保证：

[
|s_e(\hat z)-s_e(z)|\le\epsilon
]

对所有 edge 成立，那么只要

[
\boxed{
\Delta>2\epsilon
}
]

就有：

[
\arg\max_es_e(\hat z)
=====================

\arg\max_es_e(z).
]

这意味着：

> UAV 不需要把位置、belief、channel、全部 sensing state 高精度传完；只需要传到**不会改变结构决策**的精度。

如果 score 是 Lipschitz：

[
|s_e(z)-s_e(\hat z)|
\le L_e|z-\hat z|,
]

那么 bits/blocklength 可以直接由：

[
|z-\hat z|
<
\frac{\Delta}{2L_{\max}}
]

决定。

于是形成非常干净的链：

[
\boxed{
\text{sensing decision gap}
\rightarrow
\text{required information accuracy}
\rightarrow
\text{quantization bits}
\rightarrow
\text{blocklength/airtime}
\rightarrow
\text{U2U energy}.
}
]

我认为这比“再设计一个通信权重”有明显更强的创新性。

# 十三、最终建议的系统主线

我建议把 Architecture-v2 最终压缩成：

[
\boxed{
\text{Physical Capability}
\rightarrow
\text{Capability Margin}
\rightarrow
\text{Fast Distributed Allocation}
\rightarrow
\text{Slow Margin Geometry}
\rightarrow
\text{Decision-Sufficient Communication}
}
]

其中物理层定义：

[
a_{ijq}(\mathbf x)
==================

I_{\rm support}
|A(\tau,\nu)|^2
\frac{C_{ijq}}
{R_{iq}^2R_{jq}^2}.
]

在独立/已白化 sensing evidence 条件下：

[
D_q
===

\sum_{ij}
a_{ijq}p_{ijq}.
]

定义：

[
m_q=D_q-D_q^{req}
]

或者

[
m_q=\log(D_q/D_q^{req}).
]

快速层每 slot：

[
\max_{p,\mathcal E}\min_qm_q
]

——固定结构时继续用现在扎实的 LP。

慢速层：

[
\max_v\min_q
\nabla m_q^Tv.
]

通信层：

[
\min B_{\rm report}
]

subject to

[
\Pr(\text{distributed decision}
===============================

\text{full-information decision})
\ge1-\delta.
]

这三层使用的是**同一个 task variable (m_q)**。

这会比当前：

```text
range product
+ 320 m threshold
+ saturation rule
+ DD binary gate
+ LP
+ repair
+ MARL
```

明显更收敛。

# 十四、还有一个感知层 Gate 必须补：多 UAV evidence 是否真的可以线性相加

当前 max-min LP 隐含：

[
D_q=\sum_eD_{eq}.
]

只有在 local detector statistics 独立，或者经过 whitening 后，这才自然成立。

更一般地：

[
\boxed{
D
=

(\mu_1-\mu_0)^T
\Sigma^{-1}
(\mu_1-\mu_0).
}
]

若多个 bistatic links 使用同一 illuminator、同一目标散射系数、共享 clutter 或相关 waveform，(\Sigma) 不一定是 diagonal。

因此论文前一定要做一个 **evidence correlation Gate**。

如果 empirical off-diagonal correlation 很小，就可以堂堂正正写：

> 独立/近似白化假设得到 additive deflection。

如果不小，就不要强行保持简单求和，可以用低秩 covariance correction 或 conservative lower bound。

这一 Gate 很重要，因为它决定整个 LP 的物理合法性。

# 最终判断

这个仓库**现在不需要再大规模“增加算法”**。

最新一次删除被证伪 V3/congestion mechanisms 是对的；下一阶段应该更激进地继续做理论收敛。

我会把当前系统评价为：

**代码成熟度：较高；实验工程能力：较高；数学优化骨架：已有扎实部分；分布式定位：方向正确；但物理闭环和系统唯一性仍未完全封口。**

最值得保留的是：

**fixed-structure max-min LP、分布式本地协调思想、deflection→(P_D) 映射、OTFS DD 物理接口。**

最应该放弃或重写的是：

**固定 `R_crit`、range-product=steepest-descent 的论证、binary DD gate、当前 L0 bandwidth KKT、receiver-specific broadcast codeword，以及任何依赖 simulator truth 的“分布式”路径。**

而最值得作为下一阶段真正创新核心的是：

[
\boxed{
\textbf{Capability-Margin Distributed ISAC}
+
\textbf{Decision-Sufficient U2U Communication}
}
]

它把**通信开销为什么可以减少、哪些信息必须传、目标 detection 为什么能保证、UAV 为什么朝这个方向移动、功率为什么可以安全释放**统一到了同一个数学对象上。相对于继续加 MAPPO/repair 模块，这条路线更加符合 TWC/TSP 风格，也更容易建立 theorem–algorithm–experiment 的完整闭环。

如果按优先级只做下一件事，我建议**先不要跑新的性能 Gate，而是做 C0+C1：冻结唯一 canonical post-G2 system，然后把 Doppler、OTFS support/ambiguity、sensing 时间—能量三件事一次性封口**。之后再重写 Phase A，收益会比继续调当前 Phase A/B/C 更大。

我也可以持续检查这个分支后续提交，并按这套 C0–C8 Gate 重新审计。
