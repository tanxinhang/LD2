当前最容易重新跑偏的地方，是看到还有 6/100 失败，就继续增加 L3、MAPPO、结构搜索、隐蔽性等模块。

# 二、第一优先级：先处理 B5，而不是先写 D1.10-C

这一点我建议和你现在总结里的顺序**反过来**。

B5 是真正的论文正确性问题：

[
\Delta p
\leftarrow
\frac{d_{\max}}{|\Delta p|}\Delta p
]

在超出圆盘时把不同原始动作映射到同一点，是一个多对一变换。因此 PPO 中使用的

[
\log\pi(a|s)
]

并不是最终执行动作的真实概率密度。

这不是“效果可能差一点”，而是：

> **PPO importance ratio 的数学定义本身不再严格成立。**

虽然现在解析 L0/L1/L3 已经覆盖了很大一部分最终执行路径，但只要论文仍然声称 MAPPO actor 是训练系统组成部分，这个问题就不能留着。

### 最干净的修法

不要继续“Gaussian → radial clipping”，而改为一个从 (\mathbb R^2) 到速度圆盘内部的一一映射：

[
z\sim\mathcal N(\mu,\Sigma),
]

# [ \boxed{ \Delta p

d_{\max}
\frac{z}{\sqrt{1+|z|^2}}
}
]

它具有几个很好的性质：

- 严格满足 (|\Delta p|<d_{\max})；
- 不需要 clipping；
- 是一一光滑映射；
- 保持径向结构；
- Jacobian 可以精确计算。

对于二维动作，

# [ \left| \det \frac{\partial \Delta p}{\partial z} \right|

\frac{d_{\max}^2}
{(1+|z|^2)^2},
]

因此

# [ \log \pi_{\Delta p}

## \log\pi_z

2\log d_{\max}
+
2\log(1+|z|^2).
]

这样 PPO ratio 就重新具有严格意义。

**B5 修复后不要大规模重新调参。** 做一轮训练正确性验证、4/4 anchor non-regression 和解析栈兼容性检查即可。否则又会重新打开已经收敛的学习问题。

# 三、然后再做 D1.10-C，但需要彻底改变 trigger 思路

D1.10-B 已经给了一个很重要的负结果：

> 不能再根据普通 deficit、(t^*) 或 (\lambda^*) 大小简单决定“大家向瓶颈目标移动”。

因为 seed 615 的本质不是“大家离目标不够近”，而是：

[
\boxed{\text{有限 UAV 功率预算下的结构性资源拥塞}}
]

也就是说，下一版 D1.10-C **不应该再是一种新的运动规则**。

它应该是一个：

[
\boxed{
\text{geometry / power / structure bottleneck router}
}
]

## 一个比较干净的理论路由

当前其实已经有足够的量来做这个判断。

设：

- (t_{\rm fix})：当前固定结构下，lex-L1 能达到的能力；
- (t_{\rm relax})：相同几何下，放松 owner / support 等结构约束的上界；
- (d_{\rm req})：QoS 对应要求。

那么：

[
t_{\rm relax}<d_{\rm req}
]

说明即使放松结构也达不到：

[
\Rightarrow\boxed{\text{geometry-limited}}
]

交给 L3。

而如果

[
t_{\rm fix}<d_{\rm req}\le t_{\rm relax},
]

则说明：

> 几何本身有能力，但当前结构无法兑现这种能力。

此时才允许：

[
\Rightarrow\boxed{\text{D1.10-C structure repair}}
]

而如果

[
t_{\rm fix}\ge d_{\rm req},
]

则：

[
\Rightarrow\boxed{\text{No-op / L1 only}}
]

这比之前的 deficit trigger 强很多，因为它直接来自你已经建立的**同几何能力分解**，而不是再造一个经验阈值。

# 四、D1.10-C 的核心也不要做“全局重构”，只做 per-UAV congestion relief

seed 615 暴露的是：

> 某个稀缺 UAV 同时成为多个瓶颈目标的主要 supporter，导致其 1 W 预算被多个目标竞争。

所以可以利用 L1 的对偶信息。

对于目标价格 (\lambda_q) 和 UAV 功率预算价格 (\beta_i)，某条候选支持边的 reduced-cost 类型量可以写成

# [ r_{iq}

\lambda_q a_{iq}-\beta_i.
]

直观意义：

- (\lambda_q) 大：目标很缺资源；
- (a_{iq}) 大：UAV (i) 对这个目标有价值；
- (\beta_i) 大：UAV (i) 自身的功率已经很稀缺。

因此 D1.10-C 不需要枚举整个全图，可以检测：

[
\text{一个 UAV 是否同时服务多个 }\lambda_q>0
\text{ 的瓶颈目标且预算饱和}.
]

例如 UAV 2 同时承担四个瓶颈目标，就属于典型 coupling hotspot。

然后只生成小规模候选：

[
(i,q)
\rightarrow
(k,q),
]

即把一个目标的 support / owner / TX responsibility 从拥塞 UAV (i) 转移给次优 UAV (k)。

再重新跑当前的 lex L1。

### 接受规则必须非常严格

不要再出现 rev3 那种：

> seed 615 救活了，但正常 seed 变差。

D1.10-C 应采用真正的 lexicographic acceptance：

[
\text{QoS feasibility}
\succ
\text{floor margin}
\succ
t_{\min}.
]

也就是说只有以下情况才接受：

1. infeasible → feasible；
2. 或 feasibility 不变但 floor violation 严格下降；
3. 或全部 floor 状态相同但 (t_{\min}) 严格上升。

否则：

[
\boxed{\text{No-op}}
]

这样 D1.10-C 才是“结构修复器”，而不是第四套主控制器。

------

# 五、而且 D1.10-C 必须保持真正的分布式语义

这里尤其不能退回全局结构 optimizer。

建议保持：

[
\text{owner price}
\rightarrow
\text{local UAV bid}
\rightarrow
\text{small candidate}
\rightarrow
\text{finite-round power recertification}.
]

具体可以让：

- owner 发布目标价格 (\lambda_q)；
- UAV 本地计算 (a_{iq}) 和自己的 budget scarcity；
- 每个 UAV 只返回少数 best alternative bid；
- owner / 局部协调节点生成 1-swap、最多 2-swap；
- 最后仍由已有的有限轮 Dantzig–Wolfe / lex L1 重算。

于是 D1.10-C 的创新点就不是：

> “我们又设计了一个 heuristic。”

而是：

> **利用目标对偶价格与 UAV 资源价格识别局部结构拥塞，并通过稀疏责任迁移释放共享 RF 资源。**

这个理论定位要强很多。

# 八、C2 / C4 / C5 的处理方式也应该不同

### C2：值得处理

如果论文还把 single-duplex oracle 称作“upper bound”，最好做一次小规模 exact MILP。

不需要把 MILP 变成部署算法。

只需要在代表性 seed 上求：

[
\text{heuristic oracle}
\quad vs\quad
\text{exact McCormick MILP}.
]

如果 gap 很小，就获得真正的结构 upper bound 证据。

如果暂时不做，那么论文必须把措辞改为：

> heuristic structural reference

而不能再说严格 upper bound。

------

### C4：不建议通过“把门变平滑”来修

当前

# [ a_{ijq}

\mathbf 1[g_{dd}\ge g_{\min}]
\tilde a_{ijq}
]

确实在边界不连续。

但没有必要为了证明 Lipschitz 就修改物理模型。

更合理的是把理论改成**局部 active-set 定理**。

设

[
m_{ijq}=g_{dd,ijq}-g_{\min}.
]

如果 trust region 半径 (r) 满足

[
|m_{ijq}|>L_g r,
]

则该 trust region 内不会穿越 DD support 边界，indicator 固定。

于是局部区域内：

[
a_{ijq}(x)
]

重新是光滑/Lipschitz 的。

如果这个条件不能满足：

[
\boxed{\text{certificate fail-closed}}
]

就够了。

这个处理比人为 soft-gate 更符合你现在“尊重物理和数理常识”的路线。

------

### C5：不要再优化

2B 松 900 倍不是什么必须解决的问题。

它只需要被准确定位为：

[
\boxed{\text{safety certificate, not trigger}}
]

证明它安全即可，不需要证明它尖锐。

继续把时间花在把一个安全上界从 900× 缩到 50×，对论文主贡献几乎没有收益。

# 九、MKL 应当工程闭合，但不要变成研究方向

Windows/MKL `eigvalsh` native abort 最大的问题不是性能，而是**无法复现实验**。

建议直接做进程级隔离：

```text
主 evaluation process
        |
        +-- seed worker process
               |
               +-- belief eigendecomposition
```

用 `spawn`，并固定每个 worker：

```text
MKL_NUM_THREADS=1
OMP_NUM_THREADS=1
```

native crash 只杀 worker，由父进程 fail-closed 记录 seed。

目标不是让 `eigvalsh` 永远不崩，而是：

[
\boxed{\text{单 seed 数值库崩溃不能杀死整次认证}}
]

做到自动化就够了。

## 最关键的一次路线调整
