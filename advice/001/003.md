## 1. 先做一个必须的 sanity check：你的表不是严格意义上的一条 Pareto frontier

你现在得到：

| worst floor | max mean steady |
| ----------- | --------------- |
| 0.30        | 0.885           |
| 0.50        | 0.893           |
| 0.60        | 0.901           |
| 0.70        | 0.900           |
| 0.80        | 0.908           |

对于**同一个固定帧**，定义

# [ S_f^\star(w)

\max_p S_f(p)
\quad
\text{s.t. } W_f(p)\ge w.
]

因为 (w) 越大，可行域只会缩小：

[
\mathcal F_f(w_2)\subseteq\mathcal F_f(w_1),
\qquad w_2>w_1,
]

所以基本数理常识要求

[
\boxed{
S_f^\star(w_2)\le S_f^\star(w_1)
}
]

只要两者都可行。

因此单帧 Pareto 曲线绝不能出现：

[
S^\star(0.8)>S^\star(0.6).
]

你现在均值会上升，最可能不是 solver 有错，而是：

> **随着 (w) 提高，困难帧被判 infeasible 后从均值里消失了。**

例如：

[
230\rightarrow152\rightarrow126
]

个可行帧，计算 steady 均值时样本集合也变了。

所以这个结果应该表述为：

[
\boxed{
\text{conditional mean optimum over feasible frames}
}
]

不能直接称为整体 Pareto frontier。

建议马上加一个单测：

[
w_2>w_1,\quad
f\in\mathcal F(w_2)
]

必须满足

[
S_f^\star(w_2)
\le
S_f^\star(w_1)+10^{-6}.
]

如果大量违反，才是真的优化器有问题。

这个检查很重要，因为后面的理论全部建立在能力区域上。

# 2. “约 66% 功率层就够”目前也要稍微收紧

当前正式 QoS 是：

[
W\ge0.60,
\qquad
T_3\ge0.70,
\qquad
S\ge0.80,
]

其中 (T_3) 是 bottom-3 average。当前系统总纲也是这样定义 QoS 的。

你现在证明的是对于 152 个帧：

[
W\ge0.60
]

可行，并且这些可行帧的**最大 steady 平均值**约为 0.901。

还不能推出每一个这 152 帧都同时满足

[
T_3\ge0.70,\qquad S\ge0.80.
]

所以目前最准确的说法是：

> **固定功率层在相当一部分帧中存在同时改善 worst 与 steady 的明显能力，过去观察到的 worst–steady 冲突确实主要是 scalarization 造成的；完整 QoS 可行率仍需加入 bottom-3 条件逐帧验证。**

有一个很好的下界：如果某一帧能实现

[
W\ge0.80,
]

那么自动有

[
T_3\ge0.80,\qquad
S\ge0.80.
]

所以 `w=0.8` 可行的那些帧是**确定的 full-QoS feasible**。

# 3. 修完这两点以后，D0.93-A 非常值得做

而且我建议不要叫：

> “0.6/0.8 约束下的 bargaining”

更抽象地定义成：

[
\boxed{
\textbf{Task-Constrained Bargaining Allocation}
}
]

首先定义一般任务参数：

[
\xi=(\rho_{\min},\rho_{\rm tail},\rho_{\rm avg},k).
]

这只是**任务需求**，不是算法参数。

定义

[
f_q(D_q)=P_{D,q}(D_q).
]

以及

# [ W(\mathbf D)

\min_q f_q(D_q),
]

# [ T_k(\mathbf D)

\frac1k
\sum_{\text{$k$ smallest }q}
f_q(D_q),
]

# [ A(\mathbf D)

\frac1Q\sum_qf_q(D_q).
]

任务可接受集合：

# [ \boxed{ \mathcal A(\xi)

\left{
\mathbf D:
W\ge\rho_{\min},
;
T_k\ge\rho_{\rm tail},
;
A\ge\rho_{\rm avg}
\right}.
}
]

那么当前

[
(0.60,0.70,0.80,3)
]

仅仅是一个实验实例。

换任务以后，算法完全不用改。

# 4. D0.93-A 的正式优化问题应该写成

[
\boxed{
\begin{aligned}
\max_{p,\eta}\quad & \eta\
\text{s.t.}\quad
&D_q=\sum_i a_{iq}p_{iq},
\
&D_q\ge D_q^0+\eta h_q,\qquad
h_q=D_q^I-D_q^0,
\
&\mathbf D\in\mathcal A(\xi),
\
&\sum_qp_{iq}\le b_i,\qquad\forall i,
\
&p_{iq}\ge0,
\
&0\le\eta\le1 .
\end{aligned}}
]

这里两个概念彻底分开：

### 外层 feasibility

[
\mathbf D\in\mathcal A(\xi)
]

回答：

> 当前 power-only 层能不能完成任务？

### 内层 bargaining

[
\max\eta
]

回答：

> 在所有能够完成任务的功率解中，哪个解能最公平地利用剩余感知机会？

所以：

[
\boxed{
\text{Feasibility outside, bargaining inside}
}
]

现在才真正成立。

# 5. 更漂亮的是：bottom-(k) 并不会破坏凸性

这是这一轮很值得写成 Proposition 的理论点。

bottom-(k) 可以写成

# [ T_k(\mathbf D)

\min_{\substack{\mathcal S\subseteq{1,\ldots,Q}\
|\mathcal S|=k}}
\frac1k
\sum_{q\in\mathcal S}f_q(D_q).
]

所以

[
T_k\ge\rho_{\rm tail}
]

等价于：

[
\boxed{
\frac1k
\sum_{q\in\mathcal S}
f_q(D_q)
\ge\rho_{\rm tail},
\quad
\forall |\mathcal S|=k.
}
]

对于 8/8、(k=3)，就是：

[
{8\choose3}=56
]

个约束。

如果 (f_q(D)) 在工作区域内是凹函数，那么：

[
\sum_{q\in\mathcal S}f_q(D_q)
]

也是凹函数，其 superlevel set 是凸集。

因此：

[
\boxed{
W,\quad T_k,\quad A
}
]

三个 QoS 条件可以同时进入一个凸可行域。

# 7. 但我不建议把 SLSQP 当正式部署解

SLSQP 可以拿来 smoke。

不过：

> “原问题是凸的”

不等于

> “SLSQP 给我返回的结果就是可认证全局最优”。

为了符合你现在要求的理论标准，我建议分成两层。

### D0.93-A1：Exact convex oracle

用非线性凸问题直接求。

至少输出：

- primal feasibility residual；
- KKT residual；
- objective；
- 多初值一致性；
- 最好两个独立数值方法 cross-check。

这个是**数值 oracle**。

------

### D0.93-A2：Certified PWL deployment

这一层反而可能成为很好的方法创新点。

由于 (P_D(D)) 在工作区间凹，可以构造：

[
\underline P_D(D)
\le
P_D(D)
]

的分段线性 chord 下界。

然后要求：

[
\frac1Q\sum_q
\underline P_D(D_q)
\ge\rho_{\rm avg},
]

以及：

[
\frac1k
\sum_{q\in S}
\underline P_D(D_q)
\ge\rho_{\rm tail}.
]

因为

[
\underline P_D\le P_D,
]

所以一旦近似问题通过：

[
\boxed{
\text{真实检测 QoS 一定通过}.
}
]

而凹 PWL 函数可以写成有限组线性约束。

于是整个 D0.93-A2 又重新成为：

[
\boxed{\text{LP}}
]

这意味着你之前 D0.87/D0.88 的：

- 强对偶；
- Dantzig–Wolfe；
- quantized prices；
- event-trigger；
- staleness certificate

仍然有机会继续继承。

这就非常漂亮了。

# 8. 我甚至建议再增加一个“Capability Gauge”

这是比单纯 `feasible / infeasible` 更有理论价值的东西。

定义一个虚拟预算缩放系数：

# [ \boxed{ \gamma_P^\star

\min_{p,\gamma}\gamma
}
]

s.t.

[
\mathbf D(p)\in\mathcal A(\xi),
]

[
\sum_qp_{iq}\le\gamma b_i,
\qquad\forall i.
]

解释：

[
\gamma_P^\star<1
]

表示功率层不仅够，而且还有资源余量；

[
\gamma_P^\star=1
]

表示在能力边界；

[
\gamma_P^\star>1
]

表示即便把每架 UAV 的 sensing budget 按比例放大到 (\gamma_P^\star)，才能完成任务。

所以：

[
\boxed{
\gamma_P^\star\le1
\iff
\mathcal R_P\cap\mathcal A\neq\varnothing.
}
]

这就是一个非常干净的**power-layer capability certificate**。

注意 (\gamma>1) 只是诊断变量，实际执行仍严格满足 1 W，不会违反物理约束。

# 10. 最终三层就可以统一成“能力缺口”，而不是统一一个 objective

我现在会把前面“统一 bargaining value (V)”再修正一层。

真正应该统一的是：

[
\boxed{\text{Capability gap}}
]

快层：

[
G_P
]

= 固定结构需要多少额外资源才能满足任务。

结构层：

[
G_S
]

= 在合法 structure 集合中最优之后还剩多少 capability deficit。

几何层：

[
G_G
]

= 改变 geometry 后还能否消掉最后缺口。

于是：

[
G_P=0
\Rightarrow
\text{power only},
]

[
G_P>0,\ G_S=0
\Rightarrow
\text{activate structure},
]

[
G_S>0
\Rightarrow
\text{geometry required}.
]

而每一层内部再使用：

[
\text{bargaining / Pareto allocation}
]

选择具体 operating point。

这是比“一把 (\lambda) 贯穿三层”更尊重问题结构的理论框架。
